# Исправление времени фиксации снимка портфеля (v1.2)

## Причина

`PortfolioSync` сначала вызывал `GetPortfolio`, потом загружал операции,
а `PortfolioStore.save_batch()` записывал `captured_at` лишь при сохранении
в SQLite. Если в промежутке была исполнена покупка, обратный расчёт истории
ошибочно вычитал её из более раннего снимка (например, 1 − 2 = −1).

В патче время снимка фиксируется **непосредственно перед запросом GetPortfolio**;
оно передаётся в `PortfolioStore` без подмены временем записи в SQLite.
Операции, исполнившиеся после времени снимка, не используются для обратного расчёта.

Это консервативная граница: API не передаёт точное время состояния портфеля;
если сделка произошла во время запроса или разные сервисы не согласованы, 
программа по-прежнему может остановиться — это правильнее выдуманной истории.

## Установка

Остановите бота и веб-сервер. В директории проекта:

```bash
cp invest_blog/sync.py invest_blog/sync.py.bak
cp invest_blog/portfolio_store.py invest_blog/portfolio_store.py.bak
unzip -o ~/Downloads/invest_blog_anchor_fix.zip
uv run python -m pytest -q
uv run python -m invest_blog.cli sync --days 365
uv run python -m invest_blog.cli backfill --days 365
```

**Повторная синхронизация обязательна:** существующий сохранённый `captured_at`
уже ошибочен; исправление кода не изменяет его задним числом.

Если снова возникнет отрицательный остаток:

```bash
uv run python tools/inspect_anchor.py --suffix d803883c
```

Скрипт читает SQLite без изменений и выводит время снимка, количество,
сделки того же дня и отметку «до/после снимка», маскируя ID. Если 1 шт.
и покупка 2 шт. **до** снимка сохраняются, нужно сверить позиции с
`GetPositions` и проверить, не было ли продажи, перевода, погашения либо
задержки обновления сервисов T-Invest. Не используйте `--partial` для
расхождения в день последнего снимка: оно не даст безопасного интервала.

## Ограничение

Исправление не делает исторические значения равными брокерскому отчёту:
сохраняются ограничения для НКД, FX и корпоративных событий.
