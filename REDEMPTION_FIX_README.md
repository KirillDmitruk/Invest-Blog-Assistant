# Invest Blog Assistant v1.2 — исправление полного погашения облигаций

Ошибка предыдущей версии:

```
ValueError: 2026-10-15: полное погашение облигации …d89ca17e требует подтверждённого количества бумаг
```

T-Invest `GetOperationsByCursor` не гарантирует `quantity` / `quantityDone` в операциях погашения. Следовательно, удалившаяся из портфеля облигация должна быть возвращена в историю до даты погашения, но количество не всегда известно.

## Исправления

1. По каждой операции `OPERATION_TYPE_BOND_REPAYMENT_FULL` запросить профиль бумаги, даже если её уже нет в текущем портфеле.
2. Если API явно передал положительное целое число единиц — применить его.
3. Если количества нет, восстановить **только при всех условиях одновременно**:
   - выпуск обозначен как неамортизируемый (`amortizationFlag is False`);
   - номинал подтверждён в RUB и положителен (`nominal`, либо `initialNominal` для неамортизируемого выпуска);
   - сумма погашения положительная и точно равна целому числу номиналов.
4. При обратном движении по операциям прибавить количество погашенных облигаций и вычесть поступившие деньги из денежного остатка.
5. При неподтверждённом количестве не угадывать значения: обычный backfill прерывается до котировок, `--partial` восстанавливает лишь подтверждённый более поздний период.
6. В предупреждениях отобразить все погашения, количество которых восстановлено арифметически.

## Установка (Ubuntu, uv)

Остановить бота и веб-сервер.

```bash
cd ~/Projects/invest_blog_assistant
mkdir -p backups
cp invest_blog/history.py backups/history_before_redemption_fix.py
unzip -o ~/Downloads/invest_blog_redemption_fix.zip
uv run python -m pytest -q
```

Ожидаемый результат при сохранении остальных файлов и тестов последних патчей: `77 passed`.

Затем:

```bash
uv run python -m invest_blog.cli backfill --days 365
```

Повторный `sync` не нужен: исходные операции уже импортированы.

Если операция не поддаётся надёжному вычислению (амортизация, валютный номинал, нецелое отношение выплаты к номиналу, отсутствующие данные), использовать:

```bash
uv run python -m invest_blog.cli backfill --days 365 --partial
```

Это **не** полная годовая история, а только достоверно восстановленная часть. Чтобы восстановить более ранние даты, нужна подтверждённая величина погашения из брокерского отчёта и расширение модели данными об амортизации/номинале на дату.

Важно: расчётная история не включает восстановление накопленного купонного дохода и не является брокерски подтверждённой стоимостью портфеля или показателем доходности. После загрузки сравните несколько дат с официальными отчётами.
