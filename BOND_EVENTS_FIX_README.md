# Invest Blog Assistant v1.2 — полное погашение через GetBondEvents

## Почему прежний `backfill` останавливался

`GetOperationsByCursor` возвращает выплату по полному погашению, но может не возвращать количество бумаг. Если `BondBy` не содержит подтверждённого рублёвого номинала неамортизируемого выпуска, делить выплату на начальный номинал **нельзя**: бумага могла быть амортизируемой.

Метод `GetBondEvents` возвращает события погашения и **payOneBond** — фактическую сумму выплаты на одну облигацию (не путать с `moneyFlowVal` и `eventTotalVol` — суммарными значениями по выпуску). Новый код получает события погашения (`EVENT_TYPE_MTY`) и сравнивает их даты и суммы с операцией по счёту. Если выплата на счёт делится на `payOneBond` без недопустимой дробной части, количество можно восстановить. Если есть конкурирующие события/не хватает данных, автоматическая реконструкция всё ещё прерывается.

**Не путать восстановление количества с восстановлением номинала для котировок.** Если выпуск амортизировался и нет исторического номинала по датам, число бумаг может быть известно, но стоимость до погашения на графике останется неизвестной. Такая дата пропускается вместо ложной оценки.

## Установка (Ubuntu, uv)

Остановить бота и веб-сервер. В терминале проекта:

```bash
cd ~/Projects/invest_blog_assistant
mkdir -p backups
cp invest_blog/history.py backups/history_before_bond_events.py
cp invest_blog/tinvest.py backups/tinvest_before_bond_events.py
unzip -o ~/Downloads/invest_blog_bond_events_fix.zip
uv run python -m pytest -q
uv run python -m invest_blog.cli backfill --days 365
```

Повторный `sync` не требуется: `backfill` запрашивает события погашения напрямую при выполнении. `.env`, SQLite и сертификаты не меняются.

Если ошибка по погашению сохранится:

```bash
uv run python tools/inspect_redemption.py --suffix d89ca17e --day 2026-10-15
```

Скрипт выводит только фрагменты идентификаторов счёта, а также данные конкретной выплаты и доступные события; перед пересылкой вывода проверь отсутствие личных данных. Это диагностика, она ничего не удаляет.

## Ограничения

- Сопоставляются RUB-выплаты и рублёвые выплаты на одну бумагу; валютные суммы требуют FX и отдельной модели.
- Даты события/зачисления допускают сдвиг не более 7 дней. Несколько равнозначных событий не выбираются произвольно.
- Если брокер не возвращает `payOneBond` или погашение неоднозначно, нужна проверка брокерского отчёта.
- Восстановленная стоимость не включает исторический НКД и не является подтверждённой NAV.

## Состав патча

- `invest_blog/tinvest.py` — GetBondEvents;
- `invest_blog/history.py` — сверка выплаты с событием и восстановление количества;
- `tests/test_bond_events_fix.py` — регрессионные тесты;
- `tools/inspect_redemption.py` — безопасная диагностика без доступа к операциям торговли;
- `BOND_EVENTS_FIX_README.md` — инструкция.
