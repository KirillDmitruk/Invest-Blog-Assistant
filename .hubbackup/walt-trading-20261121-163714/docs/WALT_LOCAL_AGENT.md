# Walt · локальный ИИ-агент

В хабе есть отдельная страница **Walt · ИИ-агент**. Модель работает на ноутбуке через Ollama, данные получает с MCP-сервера Walt, запросы и результаты сохраняются в локальной базе. Вызовов платных API и автоматического переключения в облако нет.

Это первый этап: **анализ с правами чтения**. Агент не открывает и не закрывает реальные позиции, не переводит деньги и не работает по расписанию. Виртуальный фьючерсный счёт Т-Инвестиций на 10 000 ₽ остаётся отдельным экспериментом; он не является балансом Walt.

## Почему локальная модель

Бесплатный облачный тариф ограничивается условиями провайдера и квотами. Локальная модель не расходует облачный баланс, но использует GPU, память и электричество ноутбука. Для Walt по-прежнему нужен интернет. Комиссии, funding и риски реальной торговли от выбора локальной модели не исчезают.

Стартовая конфигурация этого ноутбука: **16 ГБ RAM, RTX 4050 Laptop, 6 ГБ VRAM**. Выбран **Qwen3 4B**, тег `qwen3:4b`, файл весов примерно 2,5 ГБ. Это проверяемый начальный вариант; размер модели и tool calling не доказывают качество торговых решений или прибыльность. Более крупную модель можно выбрать позднее после измерения скорости и памяти.

## Запуск

Ollama устанавливается с официального сайта, локальный API — `http://127.0.0.1:11434`. Если модель ещё не загружена:

```powershell
ollama pull qwen3:4b
```

Если терминал не видит команду после установки, открой новый терминал или используй:

```powershell
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" pull qwen3:4b
```

Обычно приложение Ollama запускает сервер само. Если API недоступен и приложение закрыто:

```powershell
ollama serve
```

В проекте `C:\Projects\Invest-Blog-Assistant`:

```powershell
.\hub web
```

После обновления перезапусти веб. Открой **Walt · ИИ-агент** и нажми **Проверить локальную модель**. Имя модели можно менять на этой странице; сначала загрузить её нужно через Ollama. Модели с `cloud` в названии запрещены в этой интеграции.

## Подключение к Walt

Публичный URL: `https://walletbot.me/bot-relay/public-api/mcp`.

Это обратное направление относительно прежнего Grok-коннектора: хаб выступает MCP-клиентом и сам обращается к серверу Walt. Cloudflare Tunnel, внешний адрес ноутбука и ключ xAI не нужны. Локальная OAuth-переадресация возвращает браузер в работающий хаб.

1. Открой хаб через `http://127.0.0.1:8000` или `http://localhost:8000`.
2. Нажми **Подключить Walt · только чтение**, затем открой появившуюся ссылку.
3. Самостоятельно пройди вход и подтверждение Walt. Запрашиваемая область — **`perps.readonly`**. Если показаны права торговли или неожиданные действия, не подтверждай, вернись для проверки. OAuth-коды, пароли и токены не отправляй в чат.
4. Вернись в хаб и обнови состояние. Нажми **Загрузить инструменты Walt**. Эта кнопка читает каталог и не вызывает торговые инструменты.
5. Отметь нужные инструменты чтения и сохрани настройки. По умолчанию ни один инструмент не разрешён. Неизвестные/неподходящие имена и действия записи блокируются. Если схема или описание инструмента изменились, разрешение снимается.

До входа невозможно подтвердить конкретный набор инструментов твоего счёта. Реальная авторизация и получение приватных данных требуют твоего подтверждения в Walt. Успех публичной проверки MCP/OAuth не означает, что кошелёк уже подключён.

Walt использует отдельные агентские счета и ограничивает число подключений к одному счёту. Для собственного ассистента может потребоваться **Other bot / Другой бот** и отдельный агентский счёт. Не останавливай существующий счёт ради проверки: по документации Walt остановка агентского счёта закрывает открытые позиции с комиссией.

## Анализ

Напиши задачу и нажми **Проанализировать через локальный ИИ**. Модель может вызвать до шести разрешённых инструментов чтения. Данные возвращаются в локальную модель, после чего ответ появляется в хабе и журнале. Без подтверждённого чтения данных ответ не сохраняется как анализ рынка. Если данные не помещаются в контекст или модель запрашивает неизвестный инструмент, цикл останавливается с сообщением.

Используется строгий JSON-планировщик Ollama: модель выбирает одно чтение или финальный ответ по схеме, код проверяет имя и аргументы. Свободный native tool calling у стартовой Qwen3 4B оказался нестабильным на реальном тесте; переход на структурированный формат проверен отдельно. Доступные операции ограничены закрытым списком известных чтений Walt. Методы `perps_prepare_*`, `perps_execute_operation` и `perps_readiness` запрещены; последний может запросить подготовку/создание счёта, поэтому не считается безопасным чтением.

История хранится в SQLite. Пользовательский запрос, текст ответа и имена выполненных чтений остаются локально. Данные инструментов передаются только локальной Ollama; OAuth-запросы и запросы к кошельку — только фиксированным адресам Walt. Адрес сервера и локального API не задаются моделью.

Секреты OAuth шифруются Windows DPAPI для текущего пользователя Windows. Они не выдаются через интерфейс и не отправляются модели. Копирование базы на другой компьютер не переносит работоспособный вход. PKCE S256 и одноразовое состояние защищают локальный OAuth-переход. OAuth-коды скрываются из стандартного access-журнала callback.

**Отключить локальный доступ** удаляет сохранённые локальные токены и запрещает следующие шаги анализа. Это не команда закрытия позиций и не удаление агентского счёта в Walt. Для отзыва доступа на стороне сервера проверь настройки подключений Walt. Отключение во время долгого ответа модели вступит в силу перед следующим действием.

## Реальные сделки — отдельный этап

В этой версии нет торгового OAuth scope, торгового API маршрута или команды модели для реального исполнения. Для следующего этапа нужны подтверждённые схемы инструментов Walt после входа, выбранный агентский счёт, бюджет в валюте обеспечения (в полученных схемах — USDC), разрешённые инструменты, лимит плеча, риск сделки и дневной предел потерь. Валюта пополнения и валюта обеспечения не считаются автоматически равными. Потребуется отдельная проверка исполнения/сверки и явное решение пользователя. Предложение модели сейчас не является заявкой.

## Проверки

```powershell
.\hub test
```

Тесты покрывают PKCE/state, отказ от торговых прав, шифрование DPAPI, отзыв доступа во время анализа/входа, список разрешённых инструментов, запрет выдуманных вызовов, отсутствие ответа без реальных данных, локальные маршруты и защиту изменений. Браузерный сценарий использует временную базу и подменяет проверку модели; кошелёк при этом не авторизуется.

21 ноября 2026 выполнена отдельная живая проверка после подтверждённого пользователем входа: Qwen3 4B локально вызвала `get_server_time` и `perps_latest_rate` и сохранила анализ в рабочей базе. Реальные заявки не выполнялись, баланс и позиции для проверки не читались. Ollama сообщила 100% GPU, контекст 8192 и примерно 3,9 ГБ памяти модели. По умолчанию разрешены только эти два рыночных чтения; дополнительные данные включаются на странице отдельно. В каталоге Walt обнаружено 138 контрактов, для локального анализа каталог сокращается до 12 активных по заявленному объёму с явным указанием охвата.
