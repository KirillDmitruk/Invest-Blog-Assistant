# Invest Blog Assistant 📈 → Telegram

Генератор черновиков для инвестиционного блога. **Только чтение** T-Invest API: программа не размещает заявки, не меняет портфель и не публикует посты в канал.

Полные шаблоны всех шести рубрик см. в [`TEMPLATES.md`](TEMPLATES.md).

## Функции

| Рубрика | Когда (по умолчанию — Europe/Moscow) | Данные |
|---|---|---|
| Еженедельный отчёт | Сб 10:00 | Выполненные операции ПН–ПТ: купоны, дивиденды, погашения, пополнения |
| Ежемесячный отчёт | 1-е число 11:00 | Предыдущий полный месяц + **текущий**, не исторический, снимок портфеля |
| План недели | Пн 10:00 | Купоны, объявления о дивидендах / даты выплат, последний день покупки, календарь ЦБ |
| Бумага недели | Ср 10:00 | Одна облигация/акция из портфеля, её факты + поля для собственного мнения |
| Ликбез | Пт 10:00 | Проверенные объяснения терминов, ротация |
| Пост о покупке | `/purchase` | Последняя исполненная покупка за 60 дней + вопросы для ручного заполнения |

Если дата попадает одновременно на ежемесячную и недельную рубрику — создаются оба черновика. Все операции, включая погашения и пополнения, берутся из реальных операций, без заказов на покупку в недельном отчёте.

## Запуск

Требуется Python 3.11+. В Ubuntu 24.04:

```bash
unzip invest_blog_assistant_v1_2_full.zip -d invest_blog_assistant
cd invest_blog_assistant
uv sync --extra dev
cp .env.example .env
```

1. Выпусти **токен T-Invest API только на чтение** в приложении/личном кабинете Т-Инвестиций. Запиши его в `TINVEST_TOKEN` файла `.env`. Не загружай `.env` в Git.
2. Выполни `python -m invest_blog.cli accounts`, найди нужный брокерский счёт и запиши ID в `TINVEST_ACCOUNT_IDS` (несколько — через запятую).
3. Создай Telegram-бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. Впиши токен в `TELEGRAM_BOT_TOKEN`.
4. Для первого запуска временно укажи `TELEGRAM_CHAT_ID=123` (заглушку), запусти `python -m invest_blog.cli bot` и напиши своему боту `/whoami`: он сообщит настоящий ID чата. Останови бота (Ctrl+C), поставь полученный ID в `.env` и снова запусти.
5. Выполни `python -m invest_blog.cli preview weekly` для локальной проверки отчёта, затем `python -m invest_blog.cli bot` для постоянной работы.

**Важно:** в `.env` токены и chat ID должны быть без кавычек. Папка запуска должна быть `invest_blog_assistant`, поскольку пути `DB_PATH` и `CBR_EVENTS_PATH` по умолчанию относительные.

## Бот

```text
/help       список команд
/weekly     отчет за последнюю полную рабочую неделю
/monthly    отчет за предыдущий месяц
/plan       план на текущую неделю
/paper      разбор одной текущей бумаги
/glossary   образовательный пост
/purchase   последняя покупка за 60 дней
/drafts     последние 10 черновиков
/show 12    повторно показать черновик №12
/edit 12 ... заменить текст черновика №12
/done 12    отметить самостоятельно опубликованным
/whoami     узнать ID чата
```

Можно **ответить на сообщение с черновиком** полностью новым текстом — текст заменится и сохранится в SQLite. Команда `/done` не публикует в канал, только меняет внутренний статус. Для публикации скопируй текст в канал самостоятельно.

Если черновик длиннее лимита Telegram, бот отправляет `.txt`, пригодный для копирования и правки; для сохранения правок можно использовать `/edit ID ...` или ответить на сообщение с приложением.

Черновики хранятся в `data/drafts.sqlite3`. Планировщик использует часовую зону из `.env`, не создаёт повторные **плановые** черновики за тот же период; после рестарта догоняет расписание **текущего дня**, если время уже прошло. Если бот не работал несколько дней, вручную сгенерируй пропущенные публикации с помощью команд (по умолчанию дата текущая). Отдельные ручные черновики могут повторять плановые — это сознательно, чтобы можно было обновить текст по требованию.

## Календарь ЦБ

Файл `data/cbr_events.json` содержит несколько **проверенных событий 2026 года**, сверенных по [официальному календарю Банка России](https://www.cbr.ru/eng/dkp/cal_mp/). Добавляй будущие события через запись формата:

```json
{"date":"2027-01-01", "title":"Пример — ЗАМЕНИТЬ подтвержденным событием", "source":"https://www.cbr.ru/eng/dkp/cal_mp/"}
```

**Не добавляй примерную дату, пока не проверишь источник.** Отсутствие записи означает только отсутствие события *в локальном файле*, а не отсутствие события вообще. Автоматический импорт календаря ЦБ на данном этапе не включён.

## Ограничения и корректность

- `GetOperationsByCursor` с пагинацией, статус `EXECUTED`, даты с переводом из UTC в часовой пояс отчёта.
- Суммирование **раздельно по валютам**; разные валюты не сводятся в фиктивный рублевый итог.
- Операции налогов и комиссий **не включаются** в суммы выплат. Доходность после налогов/комиссий не рассчитывается.
- Купонная дата и `paymentDate` дивидендов — ожидаемые даты, **не гарантия фактического зачисления**. Дивиденды по API выбираются фильтром по `recordDate`; для планов используется просмотр ~370 дней в прошлое и 30 дней вперёд.
- Прогнозные выплаты умножены на **текущее число бумаг**; исторический размер позиции на дату отсечки может отличаться; итог также может измениться из-за налогов и других условий.
- Кредитные рейтинги, YTM, личные причины покупки и оценочные плюсы/минусы **не выдумываются**: оставлены поля для ручной проверки и дополнения. `riskLevel` брокера не подменяет рейтинг агентства.
- Историческая доходность и исторический размер портфеля на конец прошлого месяца недоступны только из сегодняшнего `GetPortfolio`; месячный пост честно показывает текущий снимок.
- Покупка по `/purchase` берётся из последней операции: для частичных исполнений или сложных сделок надо сверить количество, среднюю цену и списание с приложением.
- При ошибке в календаре одной бумаги бот добавит видимое предупреждение; при ошибке других критичных вызовов не отправит ложный «нулевой» отчет.
- Если нет записи о будущих событиях ЦБ, это не означает, что заседаний не будет. Календарь надо обновлять из официальных источников.
- Для большого портфеля запросы к каждой бумаге могут упираться в ограничения T-Invest API. Код делает паузы и повторяет временные ошибки; при необходимости добавь кэширование календарей.
- При падении процесса **после** отправки Telegram-сообщения, но **до** записи отметки об отправке, в крайне редком случае возможно повторное сообщение после перезапуска.
- Токены не печатаются в консоль, но **Telegram-чат с черновиками содержит информацию о портфеле**. Используй личный чат и защищай свой аккаунт.

## Постоянная работа на сервере через systemd

```ini
# /etc/systemd/system/invest-blog.service
[Unit]
Description=Invest Blog Assistant
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=YOUR_LINUX_USER
WorkingDirectory=/absolute/path/invest_blog_assistant
ExecStart=/absolute/path/invest_blog_assistant/.venv/bin/python -m invest_blog.cli bot
Restart=on-failure
RestartSec=15

[Install]
WantedBy=multi-user.target
```

После замены `YOUR_LINUX_USER` и `/absolute/path`:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now invest-blog
sudo journalctl -u invest-blog -f
```

Сервис запускай ровно **в одном экземпляре**: Telegram long polling не предназначен для параллельных копий одного бота.
