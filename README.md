# Invest Blog Assistant v1.4.2

Локальный Python-проект для чтения портфеля через T-Invest API, анализа доходов/рисков и подготовки публикаций в Telegram. **Не совершает сделок**. Публикация в канал возможна только по явному одобрению черновика.

## Возможности

- v1.1: T-Invest, отчёты, Telegram-бот с редакторскими статусами, SQLite, снимки портфеля.
- v1.2: облигации, купонный календарь, реальные доходы по месяцам и восстановление доступной исторической стоимости (расчётная оценка; возможны пропуски).
- v1.3: здоровье портфеля, концентрации, риски и финансовые цели.
- **v1.4:** умный контент-план, веб-редактор, Telegram-очередь и согласование публикаций.
- **v1.4.1:** недельный график рубрик и времени, удаление неопубликованных черновиков из очереди.
- **v1.4.2:** расширенные шаблоны «Бумаги недели» и «Ликбеза», 12 подробных образовательных выпусков, безопасное разделение финансовых фактов и авторского текста.

## Установка обновления

Остановите бот и веб-сервер. Сделайте резервную копию SQLite (см. ниже), затем:

```bash
cd ~/Projects/invest_blog_assistant
unzip -o ~/Downloads/invest_blog_v1_4_2_patch.zip
uv sync --extra dev
uv run python -m pytest -q
```

`cleanup_docs.py` удаляет **только известные устаревшие .md из корня**. Не трогает пользовательскую документацию, `README.md`, `ROADMAP.md`, `TEMPLATES.md`, `.env` или данные.

## Создание резервной копии SQLite (без выключенного safety)

**Остановите оба процесса перед копированием.**

```bash
uv run python - <<'PY'
from invest_blog.config import Settings
from pathlib import Path
from sqlite3 import connect
from datetime import datetime
p=Settings.load().db_path.expanduser()
if not p.exists(): raise SystemExit(f'База не найдена: {p}')
folder=Path('backups');folder.mkdir(exist_ok=True)
out=folder/f'before_v1_4_2_{datetime.now():%Y%m%d_%H%M%S}.sqlite3'
with connect(p) as source, connect(out) as target: source.backup(target)
print('Резервная копия:',out)
PY
```

## Запуск

```bash
uv run python -m invest_blog.cli web --port 8000
# В отдельном терминале
uv run python -m invest_blog.cli bot
```

Веб-страница: http://127.0.0.1:8000 — сервер слушает **только localhost**.

Для доставки в канал по кнопке веб-редактора обязательно настроить `TELEGRAM_CHANNEL_ID` и сделать бота администратором канала. Веб-сервер **не отправляет сообщения напрямую**: он регистрирует запрос в SQLite, а работающий Telegram-бот забирает его не чаще чем раз в минуту. Если бот не работает, запрос остаётся в очереди. Отмена одобрения или редактирование черновика автоматически сбрасывает запрос.

## Изменения v1.4.2

Рубрика **«Бумага недели»** теперь содержит: интересное вступление, описание бизнеса, положение компании сейчас, показатели выпуска/акции, сценарии перспектив, преимущества, риски, личное мнение и итог. Текст после генерации — **черновик с редакторскими полями**; T-Invest не предоставляет достоверного описания бизнеса, кредитных рейтингов и прогнозов. Эти части нужно наполнить проверенными источниками, прежде чем одобрять публикацию.

Важное исправление: прежнее умножение биржевой цены облигации (часто в процентах от номинала) на количество могло показывать некорректную рублёвую стоимость. В этом шаблоне такая оценка больше не выводится; для акций рублёвая оценка остаётся, когда источник подтверждён.

Рубрика **«Ликбез за 2 минуты»** расширена до восьми смысловых элементов: заголовок, зацепка, простое определение, механизм, пример, практическое значение, типичная ошибка и вывод. Все 12 учебных текстов вынесены в `invest_blog/lessons.py`; они готовые, но финансовые и налоговые примеры остаются иллюстрациями, а не актуальными рыночными фактами. Полные структуры см. в `TEMPLATES.md`.

Обновление не меняет SQLite, настройки `.env`, расписание, Telegram-команды или веб-редактор. Существующие черновики в базе не перезаписываются: с новым шаблоном появятся **новые** черновики; для текущей недели можно сгенерировать новый вручную через `/paper` или `/glossary`.

## Изменения v1.4.1

В разделе **«Контент»** сверху отображается недельный график автоподготовки черновиков (понедельник, среда, пятница, суббота) и отдельное напоминание про ежемесячный отчёт 1-го числа. Часы и часовой пояс берутся из настроек `.env` (`PLAN_TIME`, `PAPER_TIME`, `GLOSSARY_TIME`, `WEEKLY_TIME`, `MONTHLY_TIME`, `TIMEZONE`). После изменения `.env` перезапустите **бота и веб-сервер**, чтобы отображение соответствовало работающему расписанию.

Кнопка **🗑** в списке черновиков и кнопка «Удалить из очереди» у открытого черновика требуют подтверждения. Удаление скрывает черновик из редакторской очереди и отменяет будущую отправку, включая ожидающую публикацию в канале. Опубликованные и уже отправляющиеся публикации удалить нельзя. Удаление **мягкое**: в SQLite остаётся запись со статусом `deleted`, чтобы автогенератор не создал тот же удалённый пост повторно. Это **не** физическое удаление текста из базы. Отменённая автогенерация за соответствующий период не возобновится без отдельного восстановления записи или нового ручного черновика.

Время в графике — **создание черновика**, не автоматическая отправка в канал. Автопубликации без одобрения нет.

## Вкладка «Контент»

- Календарь рубрик на ближайшие 35 дней с информацией об уже сформированных черновиках.
- Подсказки для «Бумаги недели» из позиций по последнему снимку, с учётом недавних покупок и ранее опубликованных/созданных тем; подсказки для «Ликбеза» с исключением недавних терминов.
- Форма нового черновика, список существующих, изменение текста, статусы, одобрение, планирование и запрос публикации.
- Защита от конфликтующих правок из Telegram и веба через `revision`: при конфликте нужна перезагрузка версии.
- Telegram команды `/contentplan` и `/queue`, `/cancel`; новые ручные веб-черновики отправляются в личный чат при работающем боте.

Рубрики: понедельник — план; среда — бумага; пятница — ликбез; суббота — отчёт за неделю; первого числа — отчёт за прошлый месяц. Веб-редактор создаёт также отдельные посты о покупках.

## Важные ограничения

- Данные портфеля не обновляются сами по себе при открытии веба: `uv run python -m invest_blog.cli sync --days 365` или `AUTO_SNAPSHOT=true` с работающим ботом.
- Исторический график — **оценка**, не доходность и не официальный брокерский отчёт.
- Подбор тем не является инвестиционной рекомендацией. AI-контент и новые брокеры по roadmap только в v2.0.
- Для публикации текст не должен превышать 4096 символов. При неоднозначном сбое Telegram черновик остаётся в `publishing`, и исход отправки нужно сверить в канале вручную. Автоматических повторных отправок нет.
- Не публикуйте брокерский токен, Telegram-токен или полные JSON с закрытыми данными. Используйте токен T-Invest **только для чтения**.
- Для корректного планирования постов требуется запущенный Telegram-бот. Откройте доступ к локальному дашборду только на `127.0.0.1`.

Текущие технические требования: Python 3.11+, `uv`, SQLite, FastAPI, python-telegram-bot, Chart.js (через CDN).
