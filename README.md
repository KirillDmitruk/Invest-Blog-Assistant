## v1.5.1 — мониторинг новых размещений

- При **запущенном Telegram-боте** первая проверка начинается при старте, дальнейшие — через каждые **4 часа**, APScheduler `interval`, `max_instances=1`. Если компьютер выключен, проверка не выполняется. Монитор и веб-сервер используют одну SQLite.
- Источник №1: `T-Invest InstrumentsService/Bonds` с `INSTRUMENT_STATUS_ALL`; берём только бумаги с известной `placementDate >= today`. **Это не полный аналог раздела «Будущие размещения» в приложении.** Купонный график дополнительно уточняется для первых 30 будущих выпусков, если API уже вернул его; неизвестные параметры не выдумываем.
- Источник №2: [публичный календарь Финама](https://www.finam.ru/calendar/bonds/ibo/). Даты и названия разбираются из HTML; если сайт изменит разметку или заблокирует запрос, на странице будет отдельная ошибка и ранее сохранённые данные не будут стираться. Доступность реального сайта нужно проверить на вашей машине. Отключить источник: `PLACEMENTS_FINAM_ENABLED=false`.
- Источник №3 (по желанию): собственный/разрешённый внешний JSON-календарь `PLACEMENTS_FEED_URL=https://...`, см. ниже.
- Список на веб-странице **«Размещения»**, сортировка по дате и поиск. Кнопка **«📝 Черновик»** связывает выпуск с редакторской очередью, повторное нажатие возвращает прежний черновик (если он не удалён).
- В Telegram `/start` показывает кнопку **«🛰️ Новые размещения»**. `/newbonds` открывает постраничный список по дате; выбираешь выпуск → условия → **«📝 Создать черновик»**. `/checkbonds` запускает проверку вручную. Новые/изменённые условия дают одно компактное уведомление.
- Шаблон «На радаре» <= 4000 символов; без вымышленных показателей, с полями для проверки компании, рисков и личного мнения. Публикация в канал **только после твоего одобрения** в существующем редакторе.
- T-Invest API запрещает публичную ретрансляцию данных без соответствующего разрешения. Используй полученное для внутреннего отбора, а опубликованные условия обязательно сверяй с первичными документами и разрешёнными источниками.

### Дополнительный JSON-календарь (необязательно)

В `.env` задаётся HTTPS-ссылка `PLACEMENTS_FEED_URL`. Ожидается строго такой JSON:

```json
{
  "placements": [
    {
      "id": "sample-001",
      "name": "Пример: выпуск 001Р",
      "placement_date": "2026-11-10",
      "maturity_date": "2029-11-10",
      "coupon_type": "Фиксированный",
      "coupon_frequency": 4,
      "nominal": 1000,
      "nominal_currency": "RUB",
      "source_url": "https://example.org/source-document"
    }
  ]
}
```

Это пример формата, не реальная бумага. URL должен вести к календарю, который можно получать автоматически на законных основаниях. Если календарь не задан, сканируются T-Invest и Финам.

**Ограничения:** не все будущие выпуски присутствуют у брокера; Финам может показывать только часть или отказать в автоматическом доступе; предварительные параметры меняются. Реальную полноту списка и корректность Telegram-кнопок нужно проверить на своей машине с API-токеном. Никаких сделок код не выполняет.

## Методология и качество данных

**Крайне важно:** `backfill --days 365` создаёт **приблизительную историю стоимости**, но не восстанавливает исторический НКД, корректный номинал некоторых облигаций и все валютные курсы. Поэтому она **никогда не участвует в расчёте TWR/XIRR**. Для доходности нужны два реальных брокерских снимка, подтверждённая история внешних потоков за период и согласованный набор счетов.

- **Инвестиционный результат:** стоимость на конец минус стоимость на начало минус внешние пополнения плюс внешние выводы. Это изменение стоимости капитала без отдельного выделения налогов и комиссий (они уже отражаются в брокерской стоимости).
- **XIRR:** годовая денежно-взвешенная доходность. Исходная стоимость учитывается как отток, пополнения — как оттоки инвестора, выводы — как поступления инвестору, конечная стоимость — как итоговое поступление. Если нет уникального корня, будет `н/д`.
- **TWR:** при отсутствии внешних движений в периоде — фактическая периодная доходность. Когда пополнения/выводы есть, вычисляется **сцепленный Modified Dietz** по фактическим снимкам (с временным весом операций) — это **приближение TWR, не точная TWR**. Для точной нужны оценки непосредственно в момент каждого внешнего потока.
- Купоны и дивиденды, поступившие **внутрь брокерского счёта**, являются доходом портфеля, но не внешними потоками. Продажи, погашения и покупки внутри счёта тоже не внешние потоки.
- Внешние потоки с неизвестной суммой, валютой не RUB, переводами ценных бумаг без подтверждённой стоимости, неподтверждёнными датами, нестыковкой счетов или без полной истории блокируют показатель (`н/д`). Недоступность — не нулевая доходность.
- Для движений в день снимка сравнивается фактическое время операции с `captured_at`; операции после снимка не считаются уже попавшими в его стоимость.
- XIRR годовая даже для короткого периода, поэтому может казаться непропорционально высокой/низкой; для периодов менее 30 дней показывается предупреждение.
- Сравнение 1/3/6/12 месяцев требует реального снимка начала периода не позднее чем через 7 дней после целевой даты; если его нет, показатель недоступен. В таблице указан фактический использованный период.
- Оценка текущей стоимости портфеля и денежные операции, как и прежде, должны периодически сверяться с брокерским отчётом.

**Чтобы накопить историю для полноценного сравнения**, необходимо регулярно запускать `sync` (рекомендуется раз в день). При одном только сегодняшнем снимке честная доходность за год невозможна, даже если есть все сделки за год и исторические свечи.

## Экспорт

В разделе «Доходность» есть кнопка «Экспорт ZIP + CSV». Архив содержит:

- `performance.csv` — текущий период и сравнение 1/3/6/12 месяцев;
- `broker_snapshots.csv` — **только** сохранённые полные снимки брокера;
- `external_cashflows.csv` — внешние пополнения/выводы в выбранном периоде;
- `income_by_month.csv` — агрегированные купоны/дивиденды по месяцам и валютам;
- `current_positions.csv` — текущие позиции и исходные единицы цены (для облигаций цена может быть **в пунктах**, не рублях);
- `methodology.txt`, `export_info.json` — ограничения, дата экспорта, статус.

Каждую таблицу можно скачать отдельно через локальный endpoint `/api/performance/export?table=performance` (также `broker_snapshots`, `external_cashflows`, `income_by_month`, `current_positions`). CSV сохранены в UTF-8 BOM, чтобы корректно открываться в Excel; потенциально опасные начальные символы в текстовых ячейках экранируются от CSV formula injection.

Не экспортируются токены, полные ID брокерских счетов и исходные JSON-ответы API. Доступ к веб-интерфейсу — **только 127.0.0.1**. Не публикуй этот сервис напрямую в интернете.
