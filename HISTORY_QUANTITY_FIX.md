# Invest Blog Assistant v1.2 — история количества бумаг

Этот патч исправляет обработку операций при восстановлении исторической стоимости портфеля.

## Изменения

- Проверка количества бумаг **до** запросов исторических котировок.
- Для покупок и продаж одного инструмента в один день применяется **суммарное изменение за день**, а не промежуточное состояние после каждой операции.
- Операции группируются по локальной дате из настроек T-Invest, а не слепо по UTC-дате.
- Уточнённое сообщение при невозможности обратного расчёта: дата, последний фрагмент UID, последние цифры ID счёта, начальный остаток, дельта и типы операций.
- Полное погашение облигации без подтверждённого числа списанных бумаг не интерпретируется как обычная продажа. Для дат перед таким событием нужна отдельная реконструкция.
- Режим `--partial` позволяет восстановить **только безопасный последний отрезок** времени, не подставляя нулевое количество или фиктивную цену.
- Частичная история на графике остаётся оценочной. Она не равна брокерскому отчёту и не является расчётом доходности.

## Установка

Остановить Telegram-бота и веб-сервер.

```bash
cd ~/Projects/invest_blog_assistant
mkdir -p backups
cp invest_blog/history.py backups/history_before_quantity_fix.py
cp invest_blog/cli.py backups/cli_before_quantity_fix.py
unzip -o ~/Downloads/invest_blog_quantity_fix.zip
uv run python -m pytest -q
```

`.env`, сертификаты, база SQLite не меняются. Перед любыми миграциями базы предпочтительно делать резервную копию SQLite средствами sqlite3 backup.

## Запуск

Сначала обычная команда:

```bash
uv run python -m invest_blog.cli backfill --days 365
```

Если количество не сходится, ты получишь **точную дату и типы операций** сразу после загрузки характеристик инструментов, ещё до скачивания свечей. Это не значит, что источник найден: могут быть переносы бумаг, корпоративные действия, ошибки ID или неполный период импорта.

Только если допустима неполная история, используй:

```bash
uv run python -m invest_blog.cli backfill --days 365 --partial
```

В таком режиме программа ограничивает график отрезком **после ближайшего к сегодняшнему дню проблемного события**, выводит предупреждение и число исключённых дней. Если и в этом отрезке нет достоверных котировок, прежняя история сохраняется, и команда сообщает об ошибке.

### Результаты тестирования

65 локальных тестов, включая пять новых сценариев: несовпадение количества, частичный период, внутридневные сделки, полное погашение без количества, таймзона.

### Известные ограничения

- Не поддерживается полное восстановление активов по корпоративным действиям, амортизации, переводу бумаг и иностранным валютам без дополнительной модели.
- Не заменяет сверку с брокерским отчётом.
- Не гарантирует достаточное число котировок для каждого исторического дня.
