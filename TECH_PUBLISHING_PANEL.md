# Публикация новостей в Kir in Tech News

## Независимый Telegram-режим

Поток: разрешённые RSS → свежая новость → локальный перевод EN→RU → одна публикация в Telegram. VK для этого не нужен. Используются заголовок и краткое RSS-описание со ссылкой на источник; полного AI-пересказа статей нет.

Настройки в `.env` (токен оставь существующий):

```dotenv
TECH_TELEGRAM_CHANNEL_ID=@kirintechnews
TECH_TG_AUTO_PUBLISH=true
TECH_TG_MODE=direct
TECH_TG_RUNNER=worker
TECH_TG_START_HOUR=9
TECH_TG_END_HOUR=23
TECH_TG_DAILY_LIMIT=28
TECH_TG_MAX_AGE_HOURS=24
TIMEZONE=Europe/Moscow
```

`TECH_TELEGRAM_CHANNEL_ID` — канал Tech. `TELEGRAM_CHAT_ID` — личный управляющий чат, а `TELEGRAM_CHANNEL_ID` — инвестиционный канал. Эти настройки не взаимозаменяемы. Бот должен быть администратором Tech-канала с правом публиковать сообщения.

### Первый запуск на Windows

```powershell
.\hub --translation install
.\hub translation-model
.\hub tg-test
.\hub --translation tg-news
```

- Установка модели выполняется один раз; используются официальный каталог и пакет Argos.
- Нужен совместимый Python (например, 3.13 или 3.14). При необходимости установи зависимости командой `.\hub --translation install --python 3.13`, предварительно остановив процессы проекта.
- `tg-test` без `--publish` проверяет канал и права бота через Telegram API. Сообщений не отправляет.
- `tg-news` без `--publish` показывает один подготовленный текст. Не резервирует новость и слот.

### Фоновый запуск только Tech-новостей

```powershell
.\hub news-start
.\hub news-status
.\hub news-stop
```

`news-start` проверяет переводчик и канал и запускает отдельный процесс без видимого окна. Терминал после этого можно закрыть. Повторный `news-start` не создаёт второй зарегистрированный фоновый процесс. Состояние процесса и журналы находятся в `data/tech-publisher/` и исключены из Git. `news-stop` останавливает только зарегистрированный процесс с совпадающим временем создания, включая его дочерние процессы; другие Python-процессы не затрагиваются.

Для обычного запуска в терминале:

```powershell
.\hub --translation tech-publisher
```

Остановка — **Ctrl+C**. Этот процесс не выполняет брокерскую синхронизацию, не рассылает инвестиционные посты и не использует Telegram polling.

Основной `.\hub --translation bot` тоже умеет выполнять это расписание, если выбрать `TECH_TG_RUNNER=bot`. При `TECH_TG_RUNNER=worker` он не создаёт второе задание отправки, поэтому основной бот и отдельный Tech-издатель могут работать вместе. Для Tech достаточно **одного** способа запуска. Если случайно работают два издателя, SQLite-резервирование защищает от двух отправок в одном слоте.

### Расписание и качество

- Отправка в **:00 и :30**, с **09:00 до 22:30 включительно** по Москве, до **28 попыток в день**.
- Перед каждым слотом обновляются RSS-источники. При отказе источника может использоваться сохранённая новость не старше 24 часов.
- Новостей нет, описание слишком короткое или перевод не прошёл проверку — слот пропускается. Количество публикаций не гарантируется.
- При старте нет немедленной отправки: ждём ближайшего слота. Ночные и давно пропущенные слоты не догоняются.
- Одна новость, один нормализованный заголовок и один получасовой слот резервируются атомарно. Повторные URL ранее исключаются сборщиком. Переформулированные заголовки разных статей об одном событии не гарантируют смысловую дедупликацию.
- При сетевом сбое с неизвестным результатом публикация помечается `uncertain` и автоматически не повторяется. При аварийном завершении может остаться `reserved`: проверь канал вручную.
- История отправок и последние проверки сохраняются в SQLite. Ключи и токены в текст ошибок не включаются.

Ноутбук должен быть включён, не спать и иметь интернет. При выключенном ноутбуке отправки нет; после перезагрузки Windows фоновый издатель нужно снова запустить. Автозапуск Windows и серверное размещение этой версией не настраиваются.

### Панель и ручная отправка

После изменения кода или `.env` перезапусти веб: `.\hub web`. Открой **Tech · Новости → Публикация и история**. Там показаны канал, часы, следующий плановый слот, последняя фактическая проверка и история доставки. Плановый слот сам по себе не доказывает, что процесс работает; для фонового режима проверь `.\hub news-status`.

Есть предпросмотр и кнопка **Опубликовать только в Telegram** с подтверждением. Ручная отправка тоже учитывает часы, суточный лимит и занятость текущего получасового слота. Предпросмотр не фиксирует конкретную новость за кнопкой: очередь может измениться к моменту отправки.

Эквивалентная команда реальной отправки:

```powershell
.\hub --translation tg-news --publish --confirm PUBLISH
```

Изменил `.env` — перезапусти издатель: `.\hub news-stop`, затем `.\hub news-start`. Веб и основной бот читают настройки при своём запуске.

## Прежний режим VK → Telegram

Для сохранения старого сценария укажи `TECH_TG_MODE=crosspost`, `VK_AUTO_PUBLISH=true`, `TECH_TG_AUTO_PUBLISH=true` и настрой `VK_NEWS_TIMES`, VK-группу и токен по [VK_AUTO_SETUP.md](VK_AUTO_SETUP.md). В этом режиме Telegram получает уже опубликованные в VK новости, действует прежний лимит VK 4 в день. В прямом Telegram-режиме автоматический кросспостинг из VK отключён, чтобы не возник второй поток вне расписания.
