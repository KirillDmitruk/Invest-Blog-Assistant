# Invest Blog Assistant v1.1 — обновление поверх работающего проекта

**Версия:** 0.2.0. Данные T-Invest используются **только на чтение**. Реальные операции на бирже проект не отправляет.

## 0. Безопасная установка обновления

Важно: в рабочей папке уже есть `.env`, сертификаты и база SQLite. **Не заменяйте их.** Архив обновления содержит только исходники и документацию.

```bash
cd ~/Projects/invest_blog_assistant
# Останови бота: Ctrl+C в его терминале
mkdir -p backups
cp data/drafts.sqlite3 backups/drafts_$(date +%Y%m%d_%H%M%S).sqlite3
# Если имя SQLite другое — возьми путь из DB_PATH в .env
# Распакуй скачанный инвест-патч из Downloads или Загрузки:
unzip -o ~/Загрузки/invest_blog_v1_1_patch.zip
source .venv/bin/activate
pip install -e '.[dev]'
python -m pytest -q
```

Если база была в режиме WAL при сохранении бэкапа, делай копию только при остановленном боте. Для надёжной резервной копии можно использовать SQLite Backup API.

## 1. Историческая база и первичная загрузка

```bash
python -m invest_blog.cli sync --days 365
python -m invest_blog.cli audit
```

`sync` читает все выбранные счета, получает текущие позиции и операции за 365 дней (постранично) и записывает:

- `portfolio_snapshots` — снимок рыночной стоимости по категориям в RUB, **на дату выполнения**;
- `position_snapshots` — количество/цена/валюта/дата погашения бумаги на текущую дату;
- `broker_operations` — исполненные операции за период, в разрезе исходных валют;
- `instrument_details` — справочник инструментов;
- `sync_runs` — завершённость последней успешной синхронизации;
- `editorial_topics` — какие бумаги уже попадали в рубрику «Бумага недели»;
- старые `drafts` и `telegram_messages` сохраняются, новые поля черновиков мигрируют автоматически.

> В первый запуск потребуется время, особенно для множества облигаций: T-Invest запрашивается по каждой ранее неизвестной бумаге. Повторный запуск обычно быстрее, потому что характеристики кэшируются в базе.

**Историческая стоимость:** получить точный снимок за 2025 год из сегодняшнего `GetPortfolio` нельзя; график начинается с даты первого успешного `sync`. Импорт операций за год создаёт историю полученных выплат, но НЕ прошлые цены/стоимости.

**Валюты:** `totalAmountPortfolio` и `totalAmountBonds` запрашиваются в RUB; цена позиции сохраняется в валюте инструмента. Вес рассчитывается только для цен, выраженных в RUB. Другие валюты не конвертируются искусственно.

**Качество:** отсутствующее `payment/currency` для денежных операций блокирует импорт. Ответы с плохой пагинацией блокируются существующим `TInvest.operations`. `audit` отмечает подозрительно одинаковые операции; **не удаляет их**, потому что одинаковые реальные сделки возможны. Полная сверка с официальным брокерским отчётом пока требует ручной проверки.

## 2. Веб-дашборд

```bash
python -m invest_blog.cli web --port 8000
```

Открывай **http://127.0.0.1:8000** на своём компьютере.

- Приложение принудительно слушает **только 127.0.0.1**, никакой публичный доступ без аутентификации не предусмотрен.
- Веб-приложение **только читает** сохранённые данные. Токены и ID счетов в API не отдаются.
- Графики: стоимость по дням, структура, выплаты по месяцам в RUB, оценка лестницы погашений, состав позиций.
- Рекомендации: порог доли облигаций (`BOND_TARGET`, по умолчанию 60%), максимум одной позиции (`MAX_POSITION_WEIGHT`, по умолчанию 15%), концентрация погашений, нехватка данных. Это диагностические флаги, не торговые рекомендации.
- Ещё выводятся история рубрики «Бумага недели» и состояния черновиков.
- **Chart.js** загружается с CDN для интерактивных графиков. Без доступа к CDN автоматически рисуются простые локальные Canvas-графики (без интерактивных подсказок).

**Внимание:** `GetPortfolio` возвращает текущий снимок; дневное изменение стоимости нельзя называть доходностью, оно включает пополнения, покупки и выводы. Рейтинги и классификация «голубая фишка» из названия бумаги не выдумываются.

## 3. Telegram-редактор

```bash
python -m invest_blog.cli bot
```

Теперь новые черновики приходят с кнопками. Процесс:

`Новый → На проверку → Одобрен → Опубликован` (или `Запланирован → Опубликован`).

- Кнопка **Изменить**: бот попросит отправить **полный новый текст** одним сообщением.
- Можно ответить на любое сообщение с черновиком новым текстом, либо использовать `/edit ID ТЕКСТ`.
- **Любая правка сбрасывает одобрение** и отменяет ранее назначенное время публикации.
- После **Одобрить** доступны публикация в канал и планирование.
- Для публикации добавь `TELEGRAM_CHANNEL_ID=@my_channel` (или числовой `-100...`), сделай бота администратором канала с правом публикации. Пока значение пустое — публиковать нельзя.
- Планирование: укажи в ответ `YYYY-MM-DD HH:MM` (в часовом поясе TIMEZONE). Бот проверяет очередь каждую минуту; компьютер/бот должны быть запущены.
- Если результат отправки в канал неясен, статус будет `publishing` и **автоматического повтора не будет**, чтобы не опубликовать дубликат. Проверь канал вручную.
- Для публикации в Telegram действует лимит 4096 символов; длинные тексты сначала сократи.

Бот защищён проверкой `TELEGRAM_CHAT_ID` (частный чат). Даже если пост хранится в SQLite, кнопка публикации **не выполняется** до явного одобрения.

## 4. Ежедневные снимки

Пока без VPS: можно включить внутри бота в `.env`:

```dotenv
AUTO_SNAPSHOT=true
BOND_TARGET=0.60
MAX_POSITION_WEIGHT=0.15
# TELEGRAM_CHANNEL_ID=@your_channel
```

При работающем боте снимок делается ежедневно в **21:00** по TIMEZONE. Если бот выключен, пропущенные снимки *не восстанавливаются задним числом*. Начальный импорт из терминала рекомендуем сделать с `--days 365`; регулярная синхронизация бота подтягивает операции за последние 14 дней, чтобы забирать операции с задержкой. Для более старых корректировок запускай повторно `sync --days 365`.

Пока проект работает на ноутбуке, можно вместо встроенного планировщика использовать `cron`/`systemd timer`, но не запускай одновременно два процесса бота с одинаковым токеном.

## 5. Что пока сознательно не реализовано

- **Точная инвестиционная доходность (TWR/XIRR)**: необходим корректный журнал всех внешних денежных потоков, переводов между счетами, налогов/комиссий и исторических оценок, без двойного учёта. Сейчас график стоимости — не доходность.
- **Полная сверка с брокерским отчётом**: `audit` — предварительная диагностика локальных операций. Для точной сверки надо подключить `GetBrokerReport` и обработать его выдачу по отдельной схеме, либо импорт брокерского отчёта.
- **Проверка кредитных рейтингов эмитентов и статуса «голубая фишка»**: внешние данные отсутствуют.
- **Группировка концентрации на эмитента**, если несколько выпусков одного эмитента: пока пороги относятся к **отдельному инструменту**; сводка на эмитента требует справочника эмитентов.
- **Пересчёт валют** и полная история иных брокеров — позже.
- **VPS, Docker Compose, публичный доступ к вебу** — отдельный этап. Не открывай дашборд в интернет, пока не добавлена аутентификация.
