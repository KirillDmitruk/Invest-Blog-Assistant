# Invest Blog Assistant v1.2 — исправление котировок в пунктах (`PT.`)

## Причина

При `backfill --days 365` T-Invest `GetCandles` может вернуть `priceCurrency: "PT."` для облигации. `PT.` — это **пункты цены**, а не иностранная валюта. Котировка облигации выражает процент от номинала, а её стоимость без НКД для рублёвого выпуска:

`close / 100 * nominal_rub`

В предыдущей версии `history.py` требовал `priceCurrency == 'RUB'` для любых свечей и останавливал восстановление.

## Изменения

- Для облигации с ранее проверенным рублёвым номиналом разрешены единицы `PT.`, `PT` и прежнее `RUB`; цена пересчитывается по формуле процентной котировки.
- Для акций и ETF котировка `PT.` **не** считается рублёвой.
- Иностранные котировки (`USD`, `CNY` и др.) по-прежнему вызывают ошибку без корректного механизма конвертации.
- Добавлены регрессионные тесты. Вместе с остальными тестами проекта: **60 passed** на тестовом окружении.
- База данных, `.env`, настройки Telegram и сертификаты не изменяются.

## Установка (uv, Ubuntu)

Остановите работающие бот и веб-сервер. При условии, что архив скачан в `~/Downloads`:

```bash
cd ~/Projects/invest_blog_assistant
mkdir -p backups
cp invest_blog/history.py backups/history_before_points_fix.py
unzip -o ~/Downloads/invest_blog_points_fix.zip
uv run python -m pytest -q
uv run python -m invest_blog.cli backfill --days 365
```

Ручной `sync` и переустановка зависимостей не требуются, если перед этим история операций уже была синхронизирована.

После успешного `backfill` запустите веб-сервер:

```bash
uv run python -m invest_blog.cli web --port 8000
```

Откройте http://127.0.0.1:8000, обновите график «Динамика стоимости портфеля».

## Ограничения

Исторический график — приблизительная оценка по свечам, операциям и снимкам, **не** фактический исторический NAV брокера. Исторический НКД, амортизации и валютные операции требуют отдельного учёта. При неизвестных данных скрипт не должен искусственно подставлять рубли.
