# Invest Blog Assistant v1.2 — установка через uv

**Проверка:** 37 автоматизированных тестов пройдены на имитированных данных; интеграция с вашим реальным счётом требует проверки после установки.

**Что включено:** подробнее по облигациям (номинал, НКД из текущих позиций, тип купона, купонов в год, даты погашений), купонный календарь на 12 календарных месяцев (текущий и следующие 11), фактические выплаты по месяцам, отдельные вкладки в вебе, учёт неполной истории и обновление старой SQLite без удаления таблиц. Система не отправляет торговых поручений. Тестировалась на имитированных ответах API, реальные данные брокерского счёта нужно сверить после установки.

## 1. Безопасное обновление поверх v1.1

1. **Остановите** и бота, и веб-сервер (`Ctrl+C` в каждом терминале). В `.env` сохраните read-only токен, не присылайте его никому.
2. В терминале Ubuntu:

```bash
cd ~/Projects/invest_blog_assistant
mkdir -p backups
uv run python - <<'PY'
from pathlib import Path
from datetime import datetime
from sqlite3 import connect
from dotenv import dotenv_values

source = Path(dotenv_values('.env').get('DB_PATH') or 'data/drafts.sqlite3').expanduser()
if not source.is_file():
    raise SystemExit(f'Не найден файл базы: {source}')
backup = Path('backups') / f"invest_blog_{datetime.now():%Y%m%d_%H%M%S}.sqlite3"
with connect(source) as db, connect(backup) as dst:
    db.backup(dst)
print('Копия базы:', backup.resolve())
PY
unzip -o ~/Downloads/invest_blog_v1_2_patch.zip
uv sync --extra dev
uv run python -m pytest -q
```

`unzip` меняет только файлы исходников и документации. **Не распаковывайте полную версию поверх своего проекта:** в ней пример конфигурации и не учитываются ваши локальные изменения. Патч не содержит `.env` и SQLite.

## 2. Первичная загрузка календаря и истории

```bash
uv run python -m invest_blog.cli sync --days 365
uv run python -m invest_blog.cli audit
uv run python -m invest_blog.cli bonds
```

При первом запуске v1.2 приложение запрашивает по каждой текущей облигации `BondBy` и `GetBondCoupons`. Для десятков бумаг это может занять некоторое время; следующие синхронизации используют кэш (карточки обновляются раз в 30 дней, календари — при синхронизации на новую дату). Если API не вернул расписание для части выпусков, система покажет список отсутствующих календарей и исключит устаревшие данные из прогноза. Выплаты за прошлые месяцы собираются из истории **исполненных** операций.

Календарь покрывает **текущий месяц и следующие 11**; его диапазон начинается с даты текущего снимка и заканчивается первым днём месяца после 12-го (не включая). Сумма одной выплаты = объявленный купон на 1 бумагу × текущее количество бумаг на всех выбранных счетах. Изменение количества, флоатеры, амортизации, налоги и изменение условий выпуска могут изменить фактические выплаты. Суммы не смешиваются между валютами.

Если `sync` сообщает об ошибках API по отдельным облигациям, сначала проверьте результат `bonds` и состояние доступности календарей. **Не интерпретируйте пустой прогноз как отсутствие будущего дохода.**

## 3. Запуск дашборда и Telegram

**Терминал 1:**

```bash
uv run python -m invest_blog.cli web --port 8000
```

Откройте **http://127.0.0.1:8000**. Вкладки: «Обзор», «Облигации», «Купонный календарь» (клик по месяцу фильтрует события), «Доходы», «Контент». Chart.js подгружается из CDN, без интернета включается упрощённая отрисовка Canvas.

**Терминал 2:**

```bash
uv run python -m invest_blog.cli bot
```

Существующие команды, черновики и публикации Telegram сохраняются. Если в `.env` указан `AUTO_SNAPSHOT=true`, ежедневная работа бота продолжит сохранять снимки и будет обновлять купонные данные при успешной синхронизации. Пока бот и ноутбук выключены, автоматических снимков нет.

## 4. Что означают показатели и ограничения

- **Полученные купоны/дивиденды** — денежные операции, не общая прибыль и не доходность портфеля. Налоги/комиссии в этом разделе отдельно не вычитаются.
- **Погашения** — возвращённый капитал, не прибыль. Пополнения также не доход.
- **Период без полной истории** маркируется «История неполная». После первого `sync --days 365` можно получить 12 календарных месяцев, но если портфель раньше обслуживался у другого брокера, этот импорт не заменит его историю.
- **Прогноз** по текущим позициям, а не исторический факт; купон с нулевой/необъявленной суммой становится «неизвестен».
- **Номинал** и частота купона берутся из BondBy. YTM и дюрация не рассчитываются без подтверждённых необходимых данных; кредитные рейтинги и эмитенты из названия бумаги не выдумываются.
- **Стоимость портфеля** — текущий снимок, не историческая доходность; TWR/XIRR остаются в v1.5.
- Веб слушает **только 127.0.0.1**, не открывайте его публично без защиты.

Документация T-Invest: [GetBondCoupons](https://developer.tbank.ru/invest/api/instruments-service-get-bond-coupons), [BondBy](https://developer.tbank.ru/invest/api/instruments-service-bond-by), [GetPortfolio](https://developer.tbank.ru/invest/api/operations-service-get-portfolio).

## 5. При ошибках

```bash
uv run python -m invest_blog.cli bonds
uv run python -m invest_blog.cli audit
uv run python -m pytest -q
```

Если веб не обновился, сначала убедитесь, что процессы остановлены и запущены заново, затем сделайте `Ctrl+Shift+R` в браузере.

SQLite-schema v1.2 добавляет `bond_metadata`, `bond_calendar_refresh`, `bond_coupon_events`, `operation_import_ranges`. Старые данные не удаляются. Для возврата к v1.1 остановите процессы, восстановите исходники v1.1 и **резервную копию БД v1.1**; понижать версию БД без бэкапа не рекомендуется.
