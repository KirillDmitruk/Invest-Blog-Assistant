# Content Hub: стабилизация, навигация и редакция

Изменения подготовлены локально в ветке `refactor/content-hub-workspace` на основе `origin/refactor/stabilize-editor-dashboard`. Main и рабочая база пользователя не менялись. Предпросмотр использует отдельную тестовую SQLite-базу.

## Архитектура и границы

Приложение состоит из FastAPI (`dashboard.py`), SQLite-хранилищ для инвестиций, Tech, Creator Studio и доставки публикаций, а также страницы на JavaScript. Расчёты портфеля, T-Invest, планировщик и подтверждения отправки сохранены. Очереди объединены в интерфейсе: их отдельные идентификаторы, статусы и правила публикации остаются в собственных хранилищах.

Новая навигация и инструменты вынесены в `web_static/workspace.js` и `workspace.css`. Перевод подключён отдельным FastAPI router в `editor_tools.py`. Файлы включены в пакет приложения; старые API продолжают работать.

## 1. Стабилизация

Взяты за основу исправления существующей ветки стабилизации:

- Отметка «Написан» сохраняет текст, историю тем и связи с отправленными сообщениями. Запланированная отправка отменяется; отправляющийся материал завершать нельзя.
- Ошибки отдельных запросов не блокируют весь дашборд. Доступна повторная загрузка.
- Утилита `tools/backup_db.py` создаёт согласованную SQLite-копию через online backup и проверяет её целостность.

Дополнительно:

- Обновление редакционной очереди сохраняет доступные данные при отказе контент-плана или истории тем.
- Защита несохранённых изменений применяется к инвестиционному, Tech- и Creator-редакторам. Переходы между разделами оставляют формы на месте. Переключение документа и закрытие страницы предупреждают о потере текста. Отправка и изменение статуса инвестиционного материала требуют сначала сохранить его текст.
- Убраны повторные импорты CLI. Версии видимого интерфейса приведены к версии пакета 2.4.
- Argos вынесен в дополнительную группу `translation`: его зависимость onnxruntime не устанавливается на Python 3.15. Основное приложение и тесты запускаются без этой зависимости.
- Добавлены httpx для тестового клиента и tzdata для часовых поясов Windows.
- Тесты отчётов сравнивают денежные величины через Decimal, сохраняя точность; проверки размещений используют фиксированные часы вместо текущей даты компьютера.

## 2. Навигация

| Раздел | Подразделы |
| --- | --- |
| Главная | Выбор направления |
| Аналитика | Обзор, доходность |
| Портфель | Облигации, риски, разбор ИИС |
| Денежные потоки | Фактические доходы, купонный календарь |
| Стратегия | Цели, распределение средств |
| Новые размещения | Календарь выпусков и создание черновика |
| Tech · Новости | RSS-лента, публикация и история VK/Telegram |
| Редакция | Общая очередь, инвестиции, Tech-черновики, Creator Studio |

Адрес с фрагментом (`/#desk`, `/#content`, `/#tech`, `/#news`) открывает соответствующий раздел и сохраняется при перезагрузке. На небольшом экране основное меню прокручивается по горизонтали, подразделы переносятся на следующие строки.

## 3. Единая редакция

- Общая очередь показывает последние 100 инвестиционных материалов, последние 100 Tech-черновиков и текущий Creator-план со статусами и переходом к нужному редактору.
- Поиск по названию и тексту, фильтр по направлению, независимое обновление источников. При отказе одного источника его предыдущие данные сохраняются.
- Общая панель перевода EN → RU сначала показывает редактируемый результат. Исходник не заменяется до явного нажатия «Вставить вместо текста». Применение учитывает лимит поля и блокирует изменение недоступного для редактирования инвестиционного поста.
- SEO-панель: заголовок, описание, ключевая фраза; проверка длины и присутствия фразы в заголовке и тексте. Это простые ориентиры, а не прогноз позиции в поиске.
- SEO-поля сохраняются в localStorage этого браузера отдельно по направлению и материалу. Для переноса предусмотрен экспорт JSON с текстом и SEO. В SQLite эти поля пока не хранятся.
- Публикация использует прежние сценарии: инвестиционные материалы проходят проверку и одобрение; Tech-новости публикуются отдельным механизмом VK/Telegram; Creator Studio остаётся ручным планом публикаций.

## Запуск

```powershell
uv sync --extra dev
uv run python -m pytest -q
uv run python tools/backup_db.py --db ПУТЬ_К_РАБОЧЕЙ_БАЗЕ
uv run python -m invest_blog.cli web
```

Для реального приложения нужны существующие настройки `.env` и данные. Перед использованием рабочей базы сделай резервную копию. При обновлении перенеси только код, не заменяй свою `.env` и SQLite тестовыми файлами.

Для локального перевода используй совместимую версию Python, например 3.13, дополнительную группу `translation` и установленную модель en-ru (см. `VK_AUTO_SETUP.md`). При запуске функций перевода через uv явно выбирай эту группу: `uv run --extra translation python -m invest_blog.cli web` или `uv run --extra translation python -m invest_blog.cli bot`.

Браузерная проверка требует Playwright и Chrome/Chromium, отдельного тестового приложения с несколькими материалами и установленного адреса `CONTENT_HUB_URL`. Не запускай её на рабочем экземпляре: она меняет поля в интерфейсе, хотя не нажимает сохранение и публикацию. Параметры `CONTENT_HUB_BROWSER` и `CONTENT_HUB_PLAYWRIGHT_PATH` позволяют выбрать установленный браузер и пакет Playwright.
