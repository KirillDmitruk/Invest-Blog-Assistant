# Черновики Пульса в личный Telegram через GitHub

Отдельный workflow `Private Pulse drafts` создаёт те же рубрики существующим `PostGenerator`, без переписывания личных постов ИИ. Он не публикует в Пульс или Telegram-канал, не открывает сделки и не вызывает методы брокера для торговли. Облачный ИИ рыночных сигналов настраивается отдельно.

Расписание сохраняется по Москве:

| День | Время | Черновик |
|---|---|---|
| Понедельник | 10:00 | План на неделю |
| Среда | 10:00 | Бумага недели |
| Пятница | 10:00 | Ликбез |
| Суббота | 10:00 | Недельный отчёт |
| Первое число месяца | 11:00 | Месячный отчёт |

Cron задаётся в UTC (07:00 и 08:00). При задержке GitHub черновик допускается в течение трёх часов после времени рубрики; позже автоматически не догоняется. Ручной запуск `auto` соблюдает расписание. Можно отдельно выбрать рубрику; отправка выключена по умолчанию. Локальные изменения часов требуют обновления облачного workflow — синхронизации настроек при выключенном ноутбуке нет.

## Секреты

В GitHub Actions Secrets необходимы `PULSE_TINVEST_TOKEN`, `PULSE_ACCOUNT_IDS`, `PULSE_STATE_KEY`, а также уже настроенные `SIGNALS_BOT_TOKEN`, `SIGNALS_CHAT_ID`. Используй брокерский токен только для просмотра, если создаёшь новый. Облачный клиент жёстко ограничен чтением счетов, портфеля, операций и справочников/событий инструментов. Не загружай `.env` или базу хаба в репозиторий. Ключ `PULSE_STATE_KEY` — новый ключ Fernet; он не выводится в журнал и не публикуется.

Токен брокера даёт workflow доступ к персональным данным портфеля. Его перенос в GitHub выполняется только после отдельного согласия владельца. Настройка токена не подтверждает доступность T-Invest API с облачного IP — это проверяется отдельным чтением.

Тексты, суммы, счета и ответы брокера не сохраняются в публичных артефактах или журналах. В служебной ветке `automation/pulse-drafts-state` хранится только **зашифрованный** файл `pulse-state.enc` с маркерами отправки и историей тем. Ключ остаётся в Secrets. Ошибка расшифровки или чтения состояния блокирует отправку; новое пустое состояние не подставляется. Не удаляй служебную ветку и не меняй ключ без миграции: это нарушит защиту от дублей.

Попытка фиксируется перед отправкой. Потеря ответа Telegram не вызывает автоматического повтора. Длинные тексты приходят файлом `.txt`, полностью. После подтверждённой отправки сохраняется статус `sent`. Черновики требуют твоей проверки: например, «Бумага недели» сохраняет незаполненные поля для личного мнения и исследования эмитента. Облачные черновики пока не импортируются в локальную редакционную базу.

## Включение

1. **Actions → Private Pulse drafts → Run workflow**, `send=false`: проверяются тесты и выбор расписания, брокер не вызывается.
2. После настройки секретов — ручная проверка выбранной рубрики с `send=true`. Сначала обязательно убедиться в личном получателе.
3. Для расписания установить переменную **CLOUD_PULSE_ENABLED=true**. Для остановки — `false`.
4. Чтобы одновременно запущенный локальный бот не создавал те же автоматические рубрики, установить в локальном `.env` **PULSE_CLOUD_DRAFTS_ENABLED=true** и перезапустить локального бота. Его ручные команды и редакция остаются доступны. Не запускай две независимые автоматические системы для одних рубрик.

Условия GitHub и возможные задержки расписания такие же, как для экспериментального облачного обзора. Доставка этих черновиков не означает их публикацию в Т-Инвестициях.
