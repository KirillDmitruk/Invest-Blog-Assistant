# Облачный обзор рынка через GitHub Actions

Это отдельный экспериментальный обзор публичных рынков Lighter. Он не переносит вход Walt, не видит баланс или позиции и не отправляет торговые заявки. Для сделки нужен локальный хаб со свежей проверкой Walt и твоим подтверждением. Наличие тикера на Lighter не подтверждает доступность в Walt.

## Что запускается

`Cloud market signals` читает все активные бессрочные рынки Lighter с множителем 1, до 300 без молчаливого обрезания. Для каждого проверяется непрерывная история минимум 240 закрытых часовых свечей. EMA20/50, RSI, ATR, сутки/неделя дают технических кандидатов. Объём последних 24 закрытых часов — от 1 млн; суточное изменение по модулю меньше 10%; ATR до 2,8%. Это отдельный упрощённый фильтр, а не полная стратегия Walt: фандинг, OI, расходы и исполнимость Walt здесь не подтверждены.

Cloudflare рассматривает до 8 технических кандидатов одним запросом, принимает или отклоняет готовое направление. Новости ФРС/CoinDesk за 48 часов — ограниченный и непроверенный RSS-контекст. Модель не задаёт маржу, плечо, стопы или сделки. Без ключей/при ошибке/квоте отчёт явно говорит, что проверки ИИ нет; технический кандидат не превращается в подтверждённый ИИ сигнал. Остальные рынки остаются в полном JSON-отчёте.

## Первый запуск

1. В GitHub открой **Actions → Cloud market signals → Run workflow**. Оставь `send` выключенным. Кошелёк и Telegram не вызываются. Публичные результаты находятся в Artifacts → cloud-market-report.
2. Для ИИ: **Settings → Secrets and variables → Actions → Secrets**: `CF_ACCOUNT_ID` и `CF_AI_TOKEN` из шаблона Workers AI (при ручной настройке нужны Workers AI Read и Edit). Модель фиксирована: `@cf/meta/llama-3.1-8b-instruct-fp8`. Платного переключения нет. Оставь аккаунт Cloudflare на Free без карты; доступность проверяется первым реальным запросом.
3. Для Telegram добавь `SIGNALS_BOT_TOKEN` и `SIGNALS_CHAT_ID` — **числовой ID твоего личного чата**, а не ID бота или канала. Сначала напиши боту `/start`. Получить свой ID можно из уже полученного ботом обновления `message.chat.id`; не публикуй результат `getUpdates`, он содержит личные сообщения. Код проверяет getMe/getChat и блокирует канал, группу и адрес самого бота. Не используй публичный Kir in Tech для торговых уведомлений.
4. Повтори ручной запуск с `send=true`. Это отправит один обзор, но не сделку.
5. Для автоматического анализа создай **Variables → CLOUD_SIGNALS_ENABLED = true**. Для отправок по расписанию отдельно включи **CLOUD_SIGNALS_NOTIFY = true**, только после проверки личного чата. При выключенных уведомлениях планировщик сохраняет отчёт без Telegram. Расписание: `17 */2 * * *`, UTC, каждые два часа круглосуточно на 17-й минуте (по Москве 01:17, 03:17, …, 23:17). По умолчанию расписание отключено. Для работы по расписанию файл должен находиться в основной ветке.

Не загружай `.env`, базу хаба или авторизацию Walt в репозиторий. В публичных артефактах сохраняются только рыночные данные и обзор. Отдельной подписки ChatGPT/Grok этот вариант не использует.

## Состояние и повторные отправки

Все запуски используют одну очередь без отмены текущего запуска. В служебной ветке `automation/cloud-signals-state` хранится только до 100 маркеров отправок без токена, текста личных сообщений и открытого chat_id. Нужен `contents: write` у workflow. Ошибка чтения состояния запрещает отправку. Маркер attempted записывается **до** Telegram; после подтверждения меняется на sent. Потеря ответа может привести к пропущенному уведомлению, но не к автоматическому повтору. Ключ — двухчасовой интервал UTC и отпечаток получателя. Удаление ветки/истории снимает защиту, поэтому не удаляй их для повторной отправки. Это не журнал сделок и не финансовое состояние.

## Ограничения площадок

Actions не является гарантированным торговым сервером. Расписание может задерживаться, задания — пропускаться; публичное расписание может отключиться после 60 дней неактивности. Нет постоянного процесса или контроля открытых позиций. В бесплатном приватном репозитории учитываются минуты; публичные рыночные артефакты видны другим людям. Эксперимент не означает, что GitHub одобрил использование Actions для эксплуатации бота: условия ограничивают задачи, не связанные с разработкой/тестированием/развёртыванием/публикацией проекта. Перед длительной эксплуатацией нужно учитывать это ограничение.

Источники: [GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [условия GitHub](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features), [Cloudflare Free AI](https://developers.cloudflare.com/workers-ai/platform/pricing/).

Локальная проверка: `python -m pytest tests/test_cloud_signals.py -q`. Обзор без отправки: `python -m invest_blog.cloud_signals`. Эти команды не используют авторизацию Walt и не открывают позиции.


## Сценарии v2 и читаемое сообщение

Обзор выполняется даже при нуле кандидатов на вход. Часовые свечи агрегируются в полные UTC-интервалы 4ч; неполные группы не используются. На 1ч и 4ч оцениваются EMA20/50 и наклон EMA20. Суточное/недельное изменение остаётся рассчитанным по 1ч: 24 свечи 4ч не выдаются за сутки. Истории около 20 дней достаточно для такого 4ч-контекста, но не для обоснованной длинной дневной EMA50.

Коды наблюдения: продолжение роста/снижения, отскок против старшего снижения, откат внутри роста, признаки разворота вверх/вниз, боковик. Выход за предыдущий 24-часовой диапазон считается подтверждённым объёмом при объёме часа от 1,2 среднего предыдущих 24 часов. Дивергенция RSI — только предупреждение; вершины/впадины подтверждаются двумя закрытыми свечами справа, последняя точка должна быть не старше 12 часов. Перекупленность или перепроданность сами по себе не означают разворот.

Поддержка/сопротивление берутся из предыдущих 24 часов, без последней свечи. Показаны условие наблюдения (закрытие 4ч, объём, удержание/ретест) и уровень ослабления сценария. Это не выставленные стопы и не готовые заявки. Они не учитывают ликвидацию, комиссии, фандинг, баланс и шаг цены Walt. Часовой кандидат на вход дополнительно должен совпасть с направлением 4ч; фильтры объёма, суточного движения и волатильности не ослаблялись.

ИИ разбирает до 8 наблюдений: BTC/ETH/SOL/NVDA, затем кандидаты и заметные сценарии. Он может выбрать ожидание, но не создать вход там, где код оставил wait, и не придумать цены или вероятность разворота. Новостной риск должен ссылаться на ID реально переданного заголовка. В Telegram — до 5 карточек наблюдения, время МСК, краткий фон по числу инструментов, уровни и условный совет. Не относящиеся к наблюдению новости не добавляются ради заполнения; остаётся до двух исходных заголовков, без выдачи машинного перевода за проверенный факт. Полный JSON сохраняется в Actions; предупреждение в конце сообщения не обрезается.

Эти изменения расширяют контекст и объяснимость, но **не доказывают рост точности или прибыльности**. Пороги — гипотезы. Для проверки нужны зафиксированная версия правил, независимый будущий период, исходы через 4/12/24 часа, ложные тревоги, пропущенные движения и расходы исполнения. Личный журнал сделок не используется как требование наличия сигнала. Обзор по-прежнему раз в два часа: это не мгновенное предупреждение о внутрисвечном развороте.


### Компактные сообщения

Telegram использует безопасный HTML для жирных заголовков и тикеров, время по Москве. Цвет точки отражает изменение цены за сутки, а строка индикаторов отдельно показывает тренд 1ч/4ч. Красная точка сама по себе не является советом продавать. В карточке остаются сценарий, уровень подтверждения, условие ослабления и решение ИИ. Даже без входов ИИ получает наблюдения; показанные рынки входят в его выборку до 8 сценариев. BTC/ETH дают базовый контекст, остальные карточки выбираются из ликвидных заметных движений/признаков разворота. Не относящиеся к показанным активам новости не заполняют обзор; остаётся максимум один подходящий заголовок.

Обозначение `$` — удобный формат долларовой котировки контракта Lighter; оно не переименовывает инструмент в спот-пару BTC/USDT. Баланс и валюта обеспечения Walt не читаются этим обзором. Сценарии не являются проверенными вероятностями разворота или гарантией продолжения движения. Часовые свечи и двухчасовое расписание не обнаружат каждое внезапное внутрисвечное движение. Для утверждения о повышении точности нужны независимые будущие исходы, включая пропущенные движения и ложные тревоги, а не только удачные примеры.
