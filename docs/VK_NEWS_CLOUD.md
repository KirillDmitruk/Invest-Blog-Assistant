# Дублирование новостей в VK

Назначение: https://vk.ru/club243744746. Публикуется тот же текст новости,
который подтверждённо отправлен в Telegram, со ссылкой на первоисточник.
Ссылка также передаётся как вложение VK для карточки предпросмотра.
Загрузка отдельной фотографии в VK в этой версии не выполняется.

## Подключение владельцем

1. Открыть кабинет VK ID: https://id.vk.ru/about/business/ и создать приложение
   для входа на веб-сайт. Название: Content Hub News.
2. Указать адрес сайта `http://localhost:8771` и разрешённый Redirect URI
   `http://localhost:8771/callback`. Сохранить публичный ID приложения.
   Если кабинет не принимает localhost, сначала уточнить доступные настройки
   официального приложения; не подставлять произвольный внешний callback.
3. Проверить, что аккаунт VK — администратор/редактор сообщества 243744746,
   а приложение допускает пользовательские разрешения `wall` и `groups`.
   Если `wall` не выдаётся, публикация остановится: один только вход VK ID
   с профилем/email не предоставляет права публикации.
4. В PowerShell из корня проекта выполнить (заменить число на ID приложения):

   ```powershell
   uv run --with pynacl python tools/connect_vk_news.py --app-id 12345678 --cloud
   ```

   Откроется официальный VK ID. Подтвердить запрошенные права самостоятельно.
   Команда проверит доступ к нужной стене, сохранит локальную резервную копию
   входа под Windows DPAPI и загрузит зашифрованный GitHub Secret `NEWS_VK_AUTH`.
   Она также задаст `NEWS_VK_GROUP_ID=243744746` и `NEWS_VK_ENABLED=true`.
   Ключи, коды, refresh token и адрес callback не нужно копировать в чат.
5. После успешного подключения следующий облачный цикл начнёт дублировать
   новые посты. Исторические публикации до подключения не переносятся.

Публичный ID приложения не секрет. Защищённый ключ приложения не нужен для
данного PKCE-входа. Для отправки секрета используется существующий вход GitHub
через Git Credential Manager. Не использовать чужие приложения и сайты,
предлагающие получить токен через передачу пароля.

## Работа и восстановление

- Прежнее расписание: сбор каждые 5 минут, публикация не чаще раза в 10 минут,
  с 09:00 до 23:00 МСК. У VK собственный интервал и журнал отправок.
- При работающем подключении текст помещается в отдельную зашифрованную очередь
  до отправки Telegram. VK получает его только после подтверждённой отправки Telegram.
- До вызова `wall.post` резервируется отдельная попытка VK. Неоднозначный ответ
  сохраняется без автоматического повтора. Ошибка VK не повторяет пост в Telegram.
- Ошибка предварительной проверки прав не отправляет запись и оставляет очередь
  до восстановления доступа. Очередь ограничена 50 новостями, 150 КБ и 24 часами;
  число отброшенных записей видно в статусе облака. Без ключей очередь не накапливается.
- Срок действия access token учитывается. Обновление VK ID выполняется в том же
  последовательном облачном задании; новый refresh token хранится в зашифрованном
  состоянии. Неопределённый ответ обновления требует повторного входа, а не
  повторного использования потенциально уже потраченного refresh token.
- Для переподключения повторить команду. Для отключения установить переменную
  репозитория `NEWS_VK_ENABLED=false`. Telegram продолжит работать.
- `NEWS_VK_ACCESS_TOKEN` поддерживается для совместимости с уже полученным
  пользовательским токеном; для долговременной работы предпочтителен `NEWS_VK_AUTH`.

Официальная схема VK API для `wall.post` указывает пользовательский токен:
https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json
Современный обмен кода и обновление соответствуют VK ID SDK:
https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts
