# Сделки Walt через Telegram при выключенном ноутбуке

Статус: код подготовлен, активация отдельно. Пока переменная GitHub
`WALT_TELEGRAM_ENABLED` не равна `true`, торговый обработчик не запускается,
а обзоры приходят без новых кнопок.

## Как пользоваться после подключения

1. Бот присылает обзор и кнопки расчёта лонга/шорта для трёх показанных инструментов.
2. Нажатие выбирает направление вручную. Облачный обзор не является подтверждённым
   ИИ-сигналом Walt: соответствие инструмента, цена, баланс, позиции, комиссии,
   лимиты и защитные уровни проверяются заново через существующий расчёт хаба.
3. Бот присылает маржу, плечо, риск с расходами, стоп, тейк и оценку фандинга.
   Расчётная граница ликвидации явно отличается от цены Walt.
4. Только отдельная кнопка «Подтвердить открытие · реальные деньги» отправляет
   проверенную заявку. «Отмена» ничего не открывает.
5. «Проверить заявку и позицию» сверяет состояние и защиту без повторной отправки.

Предпросмотр действует до 75 секунд. Очередь GitHub иногда запускается дольше:
просроченное подтверждение не исполняется, требуется новый расчёт и новое согласие.
Это эксперимент для ручных входов, не система скальпинга и не круглосуточное
сопровождение позиции. Защита должна быть принята самим Walt.

«Следующий сигнал» запрашивает новый обзор, не торгует. Одна кнопка не отправляет
повторные обзоры; запросы ограничены одним сообщением за пять минут.
Кнопку пополнения не добавляли: переводы денег остаются в Walt.

## Что нужно один раз настроить

Секреты добавляются в
[GitHub → Settings → Secrets and variables → Actions](https://github.com/KirillDmitruk/Invest-Blog-Assistant/settings/secrets/actions).
Значения ключей нельзя присылать в чат, добавлять в код или публичные отчёты.

* `CF_WORKERS_DEPLOY_TOKEN`: создать в
  [Cloudflare → API Tokens](https://dash.cloudflare.com/profile/api-tokens),
  шаблон **Edit Cloudflare Workers**, только нужный аккаунт. Нужны создание/изменение
  Worker и чтение workers.dev-поддомена аккаунта; DNS, домен и платное хранилище
  не используются. `CF_AI_TOKEN` остаётся отдельным ключом ИИ.
* `WALT_GH_DISPATCH_TOKEN`: создать
  [fine-grained GitHub token](https://github.com/settings/personal-access-tokens/new),
  владелец KirillDmitruk, только Invest-Blog-Assistant, **Actions: Read and write**.
  Код и Secrets этому ключу читать не требуется. Указать срок действия и обновлять
  до его истечения. Worker использует его только для запуска двух обработчиков.

После отдельного согласия на перенос создаются случайные `WALT_BUTTON_KEY`,
`WALT_EVENT_KEY`, `WALT_CLOUD_STATE_KEY`, `TG_WEBHOOK_SECRET` и сохраняются в GitHub
Secrets. Ключ состояния Walt не передаётся Cloudflare.

## Порядок переноса и включения

1. Остановить локальный хаб/бот и убедиться, что нет выполняющейся или
   неподтверждённой отправки. Не создавать новый OAuth-клиент Walt: это может
   привести к другому агентскому счёту вместо уже пополненного.
2. `tools/export_walt_cloud.py` с явным `--confirm-cloud-transfer` создаёт
   зашифрованный снимок только таблиц Walt. Он сохраняет существующие client/tokens,
   лимиты и журнал; исключает токены подтверждения старых расчётов и данные Т‑Инвестиций.
   Ключ берётся только из `WALT_CLOUD_STATE_KEY` окружения. Никаких запросов Walt.
3. Сохранить шифротекст как `walt-state.enc` в отдельной ветке
   `automation/walt-private-state`. Сохранить ключ в GitHub Secrets отдельно.
   Репозиторий публичный: шифротекст публичен; незашифрованные данные запрещены.
4. Локально установить `WALT_CLOUD_TRADING_ENABLED=true` и
   `WALT_TELEGRAM_CLOUD_ENABLED=true`. После перезапуска локальные вызовы Walt,
   обновление его OAuth-токенов и Telegram polling блокируются. Так исключаются
   конкурирующие обновления одного подключения. Остальные страницы хаба работают.
5. Сначала запустить **Deploy Walt Telegram gateway** с `activate=false`.
   Проверить развёртывание, состояние и права. Затем отдельным запуском с
   `activate=true` переключить webhook Telegram. После успешной проверки установить
   GitHub variable `WALT_TELEGRAM_ENABLED=true`.
6. Проверить обработку подписанной кнопки без отправки сделки. Первое реальное
   открытие подтверждает сам пользователь после получения карточки.

Webhook занимает входящие обновления этого бота. Локальная команда запуска бота
и прежние входящие команды редакционного бота в этом режиме не работают;
исходящие обзоры и черновики по расписанию продолжают приходить. Редакционные
действия остаются доступны в веб-хабе. Это переключение требует явного согласия.

## Защита от повторов и сбоев

Worker проверяет секрет webhook, ID пользователя/личного чата/бота, подпись и срок
кнопки. Финансовое действие в GitHub передаётся AES-GCM-шифротекстом. Подтверждение
привязано к конкретному сообщению, расчёту и хешу предпросмотра.
Использование кнопки и статус начала отправки сохраняются в зашифрованном
состоянии **до** внешнего исполнения. Сбой сохранения запрещает отправку.
Потерянный ответ означает проверку состояния, а не повтор заявки.

Обработчики последовательные; GitHub может задержать запуск или заменить
ожидающий запуск другим ожидающим. Не нажимать подтверждение повторно вслепую:
сначала проверить Walt. Сам факт запуска workflow не означает открытия позиции.
Логи и артефакты не содержат баланс, позиции, OAuth-токены или ответы Walt.

## Проверки и возврат к локальному режиму

`tests/test_walt_telegram.py` проверяет подписи, шифрование, владельца, привязку
сообщения, отмену, повторное подтверждение и отказ сохранения на заглушках.
`node tests/test_walt_worker.mjs` проверяет входящий шлюз. Реальные сделки тестами
не открываются.

Для отключения сначала убрать `WALT_TELEGRAM_ENABLED`, отключить Worker и удалить
webhook через Bot API. **Не включать старую локальную авторизацию:** облако могло
обновить refresh token. Нужен обратный перенос актуального состояния с тем же
OAuth-клиентом либо отдельное безопасное восстановление доступа. Удаление ключа
шифрования лишает доступа к облачному состоянию; токены отзываются через Walt.

Источники протокола:
[Telegram Bot API](https://core.telegram.org/bots/api),
[Cloudflare Worker bindings](https://developers.cloudflare.com/workers/configuration/multipart-upload-metadata/).
